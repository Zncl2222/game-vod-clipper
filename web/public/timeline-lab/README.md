# BossCut 時間軸設計提案

這是獨立的 HTML / CSS / JavaScript 原型，提供五種可比較的配置，尚未整合進正式 React 編輯器。

## 開啟

- 直接用瀏覽器開啟 `index.html`，無需後端、套件或外部字型。
- 或在專案根目錄執行 `npm --prefix web run dev`，開啟 `http://localhost:5173/timeline-lab/index.html`。
- 網址最後加上 `#A` 至 `#E`，可以直接開啟指定方案。
- Vite 開發模式請保留 `index.html`；僅開 `/timeline-lab/` 會進入正式應用的 SPA fallback。

## 五案

| 方案 | 結構 | 取捨 |
| --- | --- | --- |
| A 單一整合工作台 | 候選、剪輯與證據共用一組時間刻度 | 最直接消除重複；全片與局部需切換縮放 |
| B 全片導覽＋局部精剪 | 全片保留導航框，局部獨立放大 | 適合長實況；需要明確區分兩種尺度 |
| C 分步專注工作區 | 找候選、精剪、核對三步可自由切換 | 容易理解；來回比較會多一次切換 |
| D 候選卡片＋精剪 | 左邊選候選、右邊預覽與微調 | 候選內容清楚；較少全片位置資訊 |
| E 劇院＋剪輯抽屜 | 大影片搭配可收合、可調高的工作台 | 觀看舒服；收合時需要展開才可調整 |

## 目前介面的觀察

- `ClipWorkspace.tsx` 和 `AIWorkspaceTimeline.tsx` 都呈現候選、選取區間與播放位置，並從 `App.tsx` 接收相同的 `timelineView`。
- 兩區目的並非完全一致：前者能修改邊界，後者主要做原片對照，但視覺與定位操作重疊。
- `studio.css` 的 `.preview-editing` 只有 `clamp(206px, 27dvh, 260px)`，而且 `clip-range-track` 高 42px。縮放、剪輯、證據、候選、預覽操作都集中在這個區域。
- 單純增加高度，無法解決長影片縮放後把手擠在一起；要同時處理功能分工、水平寬度與局部放大。
- 首選 A；若長 VOD 的定位很頻繁，選 B，或採 A 的整合工作台＋B 的可收合全片導覽。

## 可試用的互動

方案切換、獨立的各案狀態、候選定位、時間軸定位、開始／勝利把手拖曳、方向鍵微調（Shift 為 5 秒）、時間輸入、5–10 秒收尾、示意播放、證據顯示、C 的步驟切換、E 的抽屜與高度調整、人工核對及模擬匯出。

全片時間與局部時間分別標示。查看失敗候選不會自動覆寫勝利草稿。修改時間會取消已核對狀態。勝利證據固定在示意原片的 45:02，不會跟著手動勝利標記移動。

播放只推進示意播放頭與 SVG 場景狀態。沒有讀取使用者的影片、網路請求、真實 AI 分析、草稿儲存或 MP4 匯出；重新整理頁面會重設全部原型資料。來源探索中可看到失敗候選，但預設剪輯草稿只涵蓋成功挑戰與 8 秒收尾。

桌面視窗以寬版工作台呈現，窄視窗改為堆疊；高度不足時整份提案頁可捲動，避免裁切主要控制。

## 檔案

- `index.html`：提案入口、比較表、設計理由。
- `styles.css`：沿用 BossCut 森林綠／萊姆綠視覺與響應式配置。
- `prototype.js`：示意場景、五案結構及本地互動。
- 視覺檢查截圖位於專案 `runs/timeline-lab/`，不複製或上傳原影片。
