# 預設成功挑戰搜尋與驗證

完整原片先以稀疏畫面找出遭遇，再細查勝利、進場與整場連續性。模型的信心與任務成功狀態不足以通過驗證；程式還會檢查畫面證據、時間範圍與抽樣覆蓋。

通過的候選必須具備：

- 該場戰鬥內的首領血條、決鬥、首領目標或專屬獎勵證據。技能名稱與一般敵人掉落不能確認首領身分。
- 玩家存活、對手敗北或投降，並以最後交戰與首次敗北／完成畫面定位勝利。已在戰後的畫面不能當成勝利起點。
- 競技場進場、首次戰鬥或首領登場證據，排除重生點、讀取與跑圖。同一場的前置階段與變身動畫應保留。
- 完整原片粗查、整場每 0.5 秒畫面、短範圍每 0.1 秒邊界複查，以及已釐清的死亡或重試訊號。原生細查使用來源影片的幀率。
- 已檢查的勝利後 5–10 秒收尾。

局部交戰畫面保留同場已確認的進場與結局；新的死亡證據會阻擋候選，直接重查結局可以推翻舊判斷。反覆沒有新增證據的細查有次數限制，不會無限重跑。舊版本的檢查決策不會被當成新版驗證結果直接沿用。

模型若回傳前後矛盾的候選時間，會捨棄該區間；只有另外具備首領身分、最後交戰畫面與待查結局範圍時，才保留為新的未驗證線索。先檢查最後交戰後的短間隔，再重新定位進場，不能將更晚的過場或地圖當作勝利。

## 模型與用量

首次開啟時優先選 GPT-5.6 Luna，保留使用者已儲存且仍可用的模型。預設在 Luna 搜尋時，若帳號提供 GPT-6.1 Sol，最多使用三次局部複查：首次勝利轉折、乾淨進場，以及有疑點的短轉階段。完整搜尋與一般交戰細查繼續使用 Luna。

「關鍵畫面用 Sol 複查」可關閉，對話、直接候選複查、YouTube 匯入與重試都會保留選擇。正在使用的模型、改用原因、次數與各模型實際 token 用量會記錄在任務與分析結果中。恢復任務沿用已使用的複查額度。

## 成品驗證

成品先寫入 `.partial.mp4`，檢查影像、原片音訊、影音起點與長度，並完整解碼後才改名為正式 MP4。這些檢查驗證檔案完整性；影片內容仍需預覽複查。

「播放成品」直接播放已輸出的 MP4，支援拖曳、鍵盤關閉與焦點返回，並暫停原片避免兩段聲音重疊。來源與成品不會因分析或預覽而上傳至 YouTube。
